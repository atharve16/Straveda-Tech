Runtime-created `audit_log`, `targets` and `portal_change_log` were added empty. Foreign key check passed. Source references from items and files to orders, outlet users to SAP accounts, and FOC rules to products were checked and all resolve.

MySQL `DECIMAL` columns are SQLite `TEXT` so decimal strings remain exact. Dates are ISO text. `INT`/`TINYINT` become `INTEGER`; `VARCHAR`/`MEDIUMTEXT` become `TEXT`. Original uniqueness and cascade constraints are retained. Original schema does not define foreign keys for outlet users or FOC; these relationships are validated during seed build.

Expanded tests now compare every original table's columns, declared indexes and cascade foreign keys to the SQL schema. They compare every supplied JSON field value with SQLite, check all declared DECIMAL columns use TEXT, and test that an independent in-memory copy can be changed without changing the seed. This does not test Expo's Android asset-copy lifecycle. The script's ten explicit nonunique indexes match the ten KEY declarations in the source schema; original UNIQUE constraints are retained in table definitions.

Outstanding: verify each demo bcrypt hash against `Demo@12345` in a compatible implementation, migration upgrade path, and Android first/subsequent-launch asset behavior. Python `bcrypt`, PHP CLI and other compatible implementations were unavailable in the initial environment; `pip install bcrypt` returned no available package. No hashes were replaced. PHP's `$2y$` prefix needs compatibility testing before choosing a device library. This is a seed asset, not an installable app.

Automated verification: `python -m unittest discover -s tests/database -v` passes nine tests. Hash shape was checked (`$2y$`/60 characters); password verification remains outstanding.
