# MIS module and shared dependencies: PHP source audit

## Executive summary and evidence

All **eight** `mis.php` actions were traced through `mis.php:1-47`, all 45 functions in `mis-core.php:1-600`, 25 top-level functions and the `MisCache`/`MisPivotDef` classes in `mis-xlsx.php:1-592`, and four `change-log.php` functions. Related evidence: `mis.js:1-561`, `mis.css`, `regions.php:14-193`, `users-store.php`, `auth.php`, `api.php`, `orders.php`, `index.html`, `03-demo-data/schema.sql:197-224`, `03-demo-data/demo-data.sql`, JSON seed and the existing SQLite database report. The inventory script still reports **87 actions / 305 declared functions**. This is static PHP-source auditing, not PHP runtime, workbook-layout or Android parity.

## Router-wide contract

`mis.php:16-47` starts a PHP session, decodes JSON (non-array becomes `[]`), chooses query `action` over JSON `action` and defaults to `get`. It calls `misUser()` **before** `misDB()` and `misEnsureSchema()` on every request. `misEnsureSchema` can CREATE/ALTER/seed tables, so a GET may write before dispatch; missing `seed.json` returns a warning string rather than throwing. POST alone calls `misRequireCsrf`, then `session_write_close()` releases the session lock before action execution. No per-action HTTP method allowlist exists: JSON-body GET mutation bypasses POST CSRF. Before `get`, `ver` or `download`, `misSync` may DELETE/INSERT order-derived rows and bump revision. A global `Throwable` catch rolls back an open transaction, logs the source exception and returns HTTP 500 `{ok:false,error:'Something went wrong while preparing the MIS. Please try again.'}`. `misFail` exits with `{ok:false,error}` and the specified status; `misOut` exits with `{ok:true,...}`. Download returns binary XLSX. Every route requires a session username through `misUser`; an officer deleted from `users.php` is signed out, but an outlet session is accepted without reloading its current profile in this router.

## Eight action contracts

1. **`get`** — `mis.php:32-33` → `misGet:331-350`; `mis.js:58-73` GET from opening/changing the MIS sheet, filters or page. Query `month,zone,state,q,sort,page,per,lists,pivots`; absent action defaults to get. `misWhere` filters `gone=0`, valid-shape YYYY-MM month as half-open date range, exact zone/state, escaped case-insensitive search across outlet/SAP/location/district/SA/RO/item/state/zone, plus `misScopeSql`. Malformed month is ignored; sort only `asc` gives ASC, otherwise DESC; page clamps to 1..pages; per clamps 10..200, default 100; order is date then ID. SELECT MIS rows/meta; aggregate total EA/litres, scoped month counts/litres, distinct zone/state and optional lists (sale type, zone, state, RO, SA, item; max 400 each). `pivots` truthy invokes `misPivots` and requires missing `template.xlsx`; no pivot request avoids that dependency. Success `{ok:true,rev,can_edit,is_admin,today,title,rows,total,page,pages,per,sum,months,zones,states,warn,last,lists?,pivots?}`. Any signed-in identity may read only its current scope; schema/sync can write first. Missing template on pivot request becomes 500 via global catch. Android: scoped SQLite query and local pivot model, page/filter/sort limits; tests for every filter, role, hidden rows, invalid month, limits, pivot template gap and sync-on-read.
2. **`ver`** — `mis.php:34`, browser polling `mis.js:81-87` every 20 seconds while page active. GET selector only; any signed-in actor. Pre-dispatch `misSync` may change MIS rows and `rev`, then `misMeta('rev')` returns integer (missing/null casts 0). Success `{ok:true,rev}`. No action-local write/transaction, but GET sync is a write path. Android: local revision observation after deterministic projection refresh; tests for no-op, new approved item, stale-row deletion and repeat polling.
3. **`download`** — `mis.php:35` → `misDownload:592-600`; `mis.js:313-329` Download Excel button, GET. Any signed-in actor; pre-dispatch sync. `misAllRows:277-287` selects `gone=0` with **`misScopeSql`**, ordered by ID; export is scoped to the user's MIS rows, not all production rows. `misBuildXlsx` loads `mis-data/template.xlsx`, rewrites workbook parts and returns bytes with XLSX MIME, Content-Disposition `MIS MTD <current month year>.xlsx` and length. Missing/invalid template returns 500 `{ok:false,error:'The Excel file could not be prepared. Please try again.'}`. No file write. Android: local export only after template/format decision; tests for zone/state/SA/SAP scope, missing template, data order and workbook validity.
4. **`outlet`** — `mis.php:36` → `misOutlet:580-590`; `mis.js:405-415` GET `sap` when a typed SAP fills empty row fields. Router requires a signed-in identity but helper has **no `misScope`/SAP permission guard**. SAP is trimmed; SELECT `portal_outlets` by exact code, swallowing query exception as not found. Missing returns `{ok:true,found:false}`. Found returns `{ok:true,found:true,f:{o,l,di,st,sa,ro,z,t}}`; `l` mirrors canonicalized SA, `t` is fixed `HPCL Retail Outlet`. `misCanonMaps` reads all MIS rows to choose common geography spellings; no transaction/write. Android: locally scoped reference lookup needs a product/security decision because PHP exposes cross-scope master outlets to any session. Tests: missing/invalid SAP, cross-zone visibility, canonical map, table failure.
5. **`save_row`** — `mis.php:37` → `misSaveRow:421-456`; `mis.js:382,413,422` POST JSON `id?`, `f` object of MIS short keys, optional `ver`, CSRF. `me.edit` required: non-HPCL Super Admin or Rohan `role=zone` officer. Create (`id=0`): `misCheckFields` requires valid date, validates supported keys, `misRowInScope` checks proposed geography, litres defaults to EA×20 when absent, INSERT `src=sheet,ver=1`. Update: SELECT visible `gone=0` row or 404, check old and merged new scope (403), optional `ver` equality (409), validate fields, and conditionally recalculate litres when prior value followed EA×20; empty set 400. UPDATE supplied columns, `ver=ver+1`, updater/time, **without version/status predicate or row lock**. `misLogDiff` writes `chgAdd(area=mis,added|edited)` before revision bump, but no log for numerically/visibly unchanged fields even though UPDATE/revision may occur. `chgAdd` is best effort; no transaction across row, log and `misBump`. Success `{ok:true,row:misRowOut(...),rev}`. Dates must be actual YYYY-MM-DD in years 2020–2100; numeric 0–1e9, rounded 2 decimals; text limits from `MIS_FIELDS`; item name canonicalized. Tests: create/update, all fields, outlet lookup follow-up, old/new scope, stale/omitted version, lost update, EA/litres, audit failure.
6. **`delete_row`** — `mis.php:38` → `misDeleteRow:457-472`; `mis.js:432-442` POST `id` and CSRF. Editor only; SELECT visible row or 404, require `misRowInScope` or 403. Order-derived row is UPDATE `gone=1,ver+1` (hidden marker prevents immediate resync); sheet row is physically DELETE. `chgAdd(area=mis,deleted)` records nonempty field old→null diffs, then revision bump. No transaction, lock or stale version check. Success `{ok:true,rev}`. Tests: order marker persistence, sheet removal, scope, replay, audit/revision partial failure.
7. **`delete_rows`** — `mis.php:39` → `misDeleteRows:474-509`; `mis.js:211-225` POST CSRF with either `all=true,filter:{month,zone,state,q}` or `ids[]`. Editor only. Begins one transaction. `all` uses `misWhere`, including `gone=0` and actor scope, to UPDATE matching order rows `gone=1` and DELETE matching sheet rows; filters are read from body, not locked to the UI's displayed state. It logs first 100 row descriptions. Selected IDs are integer-cast, positive and unique; empty list 400; reads/logs first 100 scoped rows, processes all IDs in chunks of 500 with scope predicate, silently ignores inaccessible IDs. There is **no maximum ID count**. Bump revision only if `n>0`, commit, then best-effort shared `chgAdd` (outside transaction because DDL would implicitly commit). Success `{ok:true,deleted:n,rev}`. No explicit row locks or version checks; global catch rolls back errors. Tests: all versus IDs, forged filter, scope, >100 log summary, >500 IDs, replay/no-op, rollback and postcommit log failure.
8. **`import`** — `mis.php:40` → `misImport:541-577`; `mis.js:481-557` POST JSON `rows[]`, `mode` (only exact `append` remains append; other/missing means replace), optional `name` and CSRF. Editor only. Empty/nonarray 400; >30,000 413; each row `misImportRow` requires valid date 2020–2100 and converts remaining known fields; invalid-date rows skipped, invalid numeric becomes NULL, text cleaned/truncated, item canonicalized and litres derived from EA when absent. If actor `misScope() !== null`, force append and skip out-of-scope valid rows; none left 422. Global editor replace transaction marks all visible order-derived rows `gone=1` and deletes **all** sheet rows, not just a month. INSERT accepted rows in 250-row batches, set `seeded` and `upload` metadata, bump revision, commit, then best-effort `chgAdd(area=mis,import)`. Success `{ok:true,imported,skipped,removed,mode,rev}`. Duplicate imported sheet rows are not deduplicated; order markers persist. Error from global catch is 500/rollback unless validation exits earlier. Android: local import transaction with explicit replacement and marker policy. Tests: 30k limit, invalid/duplicate/out-of-scope rows, scoped forced append, global replace, metadata/log, rollback and crash/retry.

### Shared identity, scope and logs

`misUser:46-56` reloads officers from `usersLoad`; an absent officer destroys the session and returns 401. Outlet identities return session username/label without rechecking `portal_outlet_users` or the current outlet master; `misScope:68-101` uses session SAP. Rohan `role=zone` is an editor regardless of regional/zone `level`; HPCL officers and HPCL Super Admin are readers. A `role=superadmin` with non-HPCL (including null) org is admin/editor. `misScope` resolves superadmin `approvalStates`; assigned states restrict scope, no states means all. Officers use current `zones` or valid filter-zone fallback and `ORD_SHEET_ZONES` region mapping. If assigned `ros` intersects zone ROs, the intersection is used; **if the intersection is empty, the code keeps every RO in the zone** (`mis-core.php:93-95`). Regional-level officers additionally need a nonempty SA list or see no rows. Outlet scope is exact SAP. `misScopeSaps` extends RO+SA scope with SAP codes from current `portal_outlets` to account for legacy SA spellings. `misScopeSql` is used for row reads, export and bulk delete; `misRowInScope` checks creates/updates/deletes. `approvalStateList:175-181` and `approvalStates:183-193` in `regions.php` remain part of the earlier auth audit; `ORD_ZONES,ORD_SHEET_ZONES,ORD_STATE_RO,ORD_RO_SA,ORD_SHEET_STATES` are bundled geography maps, not live external services.

`chgAdd:40-54` writes `portal_change_log` with area/action/target/summary, up to 60 field changes (each label 80 chars, values 300), 100 text lines and a note ≤300, actor username/label/`chgRole` and MySQL time. It catches `Throwable`, logs failure to PHP error log and never fails the underlying edit. `misSaveRow` and `misDeleteRow` call it after their row write but before revision bump; `misDeleteRows` and `misImport` call it **after commit**. `chgEnsure` creates the table on demand, which explains the latter placement. `chgFetch:57-76` is used by `orders.php change_log area=mis`, not directly by `mis.php`; it offers 50/page and search across target/summary/actor/details. `orders.php:2009-2012` has no MIS-specific geography guard, so any ordinarily authenticated orders actor reaching `change_log?area=mis` can receive shared MIS history regardless of row scope. `api.php audit_log` and `portal_order_events` are different stores. The MIS page's Log button uses the orders endpoint; its own router does not expose log viewing.

## Read model, pivots and order projection

`portal_mis_rows` is shared by MIS, API Dashboard and Raw Data (`api.php:283-338`). `misGet` is a paged/filterable projection; `misAllRows` is an unpaged scoped workbook projection. `misPivots` reads the scoped projection and original template's pivot cache/definitions; `misPivotModel:204-269` groups **litres** by month number (January through December) and template-ranked zone/RO, SA, item/state and zone/state. It carries hidden pivot items, subtotal for item/state, grand totals and blank handling from template definitions. Months are keyed by month number in code; years are not separated into distinct columns, so multi-year rows of the same month aggregate together. This is a verified calculation with a possible reporting ambiguity requiring a product decision.

`misSync:244-268` first checks that order/item tables exist. It DELETEs every `src=order` MIS row whose `item_id` no longer points to an approved, non-`historical-import` order item. It INSERT IGNOREs one row per approved nonhistorical order item lacking any matching `item_id`; `uk_item` enforces uniqueness. It canonicalizes geography against most frequent existing MIS spellings, maps item by product brand/name to workbook item constants, copies total EA and litres (FOC included), sets `src=order,item_id,ver=1,updated_by=order`, and bumps revision only if rows were deleted/inserted. It does **not** update an existing order-derived MIS row when the underlying order item/header changes; manual edits and `gone=1` markers persist while the order remains eligible. If that order becomes ineligible, the marker is deleted; later reapproval can insert a new visible row. `misSync` has no explicit encompassing transaction or lock. Draft/pending/rejected and historical-import orders do not contribute new rows. `api.php sales` performs the same sync before reading. Tests need no-op revision, canonicalization, source-edit staleness, hidden marker lifecycle, order status changes and concurrent sync.

## Excel generation and missing template

`mis-xlsx.php:14-20,23-592` reads the original ZIP package with a custom central-directory reader, edits XML and rewrites ZIP bytes using zlib. It requires `mis-data/template.xlsx` for both `get?pivots=1` and `download`. Four visible sheets are described by `mis.php:5-11`/`mis.js:11-16`: data, Region Wise, SA Wise, State wise. The code rewrites data `xl/worksheets/sheet2.xml` columns A:M, report `sheet6.xml` (zone/RO), `sheet7.xml` (SA) and `sheet8.xml` (zone/state plus item/state), pivot definitions 3–6 and cache definitions/records 2 and 3. It adds a final blank dated row for Excel pivot validity, uses Excel serial dates, preserves per-row `xs` styles or defaults, writes numeric EA/litres, and uses a `+L<row>*20` formula when litres tracks EA. It updates cache shared items/date groups, template shared-string indexes, report dimensions/columns, refresh flags, workbook filter range and removes calc chain. The original package's styles, shared strings, relationships, hidden sheets and exact visual layout cannot be verified because the template is absent. Do not fabricate an equivalent template or claim XLSX output can be validated from this kit.

The browser import is different from export: `mis.js:445-557` accepts .xlsx/.xls/.csv up to 15 MiB, loads bundled `xlsx.mini.min.js`, finds a sheet with ≥5 recognized headings (favours names matching secondary/RO_BZR), parses Excel date objects/serials and textual dates, maps up to 13 columns, derives litres, previews rows and missing columns, then sends JSON `rows,mode,name`. PHP receives no workbook file and independently validates dates, count and scope. Client-side 15 MiB/extension/header checks are not server request limits. The viewer requests pivots only for non-data tabs; the missing template therefore breaks those report tabs even though a nonpivot data GET can work.

## Security, correctness and unresolved decisions

- **Confirmed:** GET `get/ver/download` can write via schema ensure and sync (`mis.php:23-30`). JSON-body GET mutation also bypasses POST CSRF because no method allowlist (`mis.php:20-40`). Android must use explicit local commands/transactions; decide whether to retain read-time repair timing.
- **Confirmed:** `download` uses `misAllRows`/`misScopeSql` and does not export other users' normal MIS rows (`mis-core.php:277-287,592-600`). However the scoped file may include sensitive outlet dimensions; define local file-sharing/privacy rules before export.
- **Confirmed:** `outlet` requires a session through router but does not check whether the SAP is in the actor's geography or own SAP; it can return cross-zone master data (`mis.php:23,36`; `mis-core.php:580-590`). Decide whether offline lookup must be restricted.
- **Confirmed:** `orders.php change_log area=mis` calls `chgFetch` without MIS row scope (`orders.php:2009-2012`); the shared log can contain geographic row details outside a reader's usual MIS view. Decide a local history access policy.
- **Confirmed:** when an officer's assigned `ros` has no overlap with ROs in the assigned zone, `misScope` keeps every RO from that zone instead of denying access (`mis-core.php:93-95`). This can widen access relative to the configured RO list. Decide whether the Android implementation should reproduce this fallback or reject inconsistent account geography.
- **Confirmed:** all three mutation helpers guard `me.edit`; old/new scope is checked on save, row scope on single delete, and `misWhere/misScopeSql` on bulk delete. Restricted-state superadmin's `misScope()` is nonnull, so import forces append; only an unrestricted editor can replace all (`mis-core.php:421-577`).
- **Confirmed:** `save_row` version check is optional and its UPDATE has no version predicate or row lock; concurrent edits can overwrite. Single delete and bulk delete have no stale version check. `misSync` can race and has no encompassing transaction (`mis-core.php:244-268,421-509`). Decide a local conflict policy rather than silently claiming PHP guarantees.
- **Confirmed:** `chgAdd` may fail silently, leaving successful data changes without change history; single save/delete are not transactional with revision/log; bulk/import log occurs after commit (`change-log.php:40-54`; `mis-core.php:421-577`). A displayed revision is a change signal, not a complete audit trail.
- **Confirmed:** a `gone=1` order row blocks resync while its order stays approved, and existing order-derived rows are not refreshed from changed order data. A later ineligible status removes the marker (`mis-core.php:244-268`). Decide how future Android migration handles already divergent rows.
- **Potential risk:** `misDistinct` accepts a column name interpolated into SQL, but its callers in `misGet` pass fixed literals; no request-controlled column reaches it (`mis-core.php:316-350`). `misWhere` uses fixed zone/state columns and parameterized values; search escapes LIKE metacharacters. The original template XML is unavailable, so workbook parser/package trust cannot be runtime-assessed.
- **Missing source:** live `config.php`, live `users.php`, `mis-data/seed.json` and `mis-data/template.xlsx`; production MySQL contents and actual workbook package. Demo JSON has 106 MIS rows and one meta row; it does not establish live history, permissions or workbook formatting. Exact Excel/pivot parity and initial PHP seeding remain blocked.
