# STRAVEDA technical documentation

## Overview

STRAVEDA is an Android-only offline demonstration client for the Rohan Energy portal data. It is built on the existing Expo Router project and bundled SQLite demo database. Each installation receives an independent app-private copy of the seed. The original PHP portal is a read-only reference; its full behavior has not been ported.

## Architecture and technologies

Expo SDK 58, React Native 0.88.1, React 19.3, TypeScript, Expo Router and `expo-sqlite` form the client. `bcryptjs` verifies the source PHP `$2y$` demo hashes after prefix conversion. Expo Document Picker, File System and Sharing provide local CSV import/export. `app/_layout.tsx` opens and validates the database and creates two app-owned tables. `app/index.tsx` provides login and tabbed functional screens. `src/domain.ts` owns local authentication, scope checks, queries and mutations; `src/csv.ts` parses and writes CSV. `assets/database/rohan_energy_demo.db` is the source seed generated by `scripts/build_demo_db.py` from supplied demo JSON and schema.

## Offline database

The SQLite provider copies the bundled seed on first open and reuses the app-private database on later launches. Startup enables foreign keys, requires seed schema version 1 and the core portal tables, and runs `foreign_key_check`. App-owned `app_pending` and `app_history` are created idempotently. Order, MIS and outlet tables are documented in `DATABASE_MIGRATION_REPORT.md`. Each install has separate data and no synchronization. The app code uses no runtime network API. Android release config blocks `INTERNET` and `ACCESS_NETWORK_STATE`, subject to merged-manifest verification after a build.

## Authentication and permissions

Login checks officer or outlet accounts in SQLite, verifies bcrypt, requires the selected Rohan/HPCL/outlet organization, and joins outlets to the master list. Session state lives in memory; users sign in again after a cold restart. The demo credentials are `demo_super` / `Demo@12345`. Reads and writes check local geography through `inScope`. Rohan Super Admin and Rohan zone accounts can add MIS rows. Rohan Super Admin can decide pending MIS entries. Order decision eligibility is guarded by local role/scope rules. These rules are a partial implementation of `ROLE_PERMISSION_MATRIX.md`; full portal parity is not claimed. Device-local security cannot protect against a modified APK or rooted-device database editing.

## Modules

- Dashboard: scoped counts and MIS litres from SQLite.
- MIS: scoped recent rows, search, validated add/edit/delete, transactional append import from CSV and scoped CSV export through Android sharing. Workbook import and bulk delete remain pending.
- Orders: scoped recent orders, one-item draft creation, creator submission and approval/rejection of eligible pending orders. Approval checks stock, snapshots price/GST, assigns local voucher/invoice identifiers and adds missing order-item MIS projections in one transaction. Portal PDF documents are pending.
- Pending: submit a validated local MIS entry; Rohan Super Admin approval inserts a MIS row atomically and rejection records a reason. A decided entry cannot be decided again.
- Reports: on-screen local summary and scoped MIS CSV export.
- History: app-owned activity for these new mutations. Existing portal order events are written for order decisions.

## Source layout and development

`app/` contains Expo routes, `src/` domain logic, `assets/database/` the seed, `scripts/` inventory/seed/offline checks, `tests/database/` seed tests, and `docs/` source audits and submission docs. From a clean checkout, install Node.js and Python 3, then run `cd client`, `npm ci --legacy-peer-deps`, `npm run typecheck`, `python -m unittest discover -s tests/database -v`, and `npx expo start`. For an Android APK, sign in to EAS and run `npx eas-cli build --platform android --profile production-apk`; first build requires EAS Android signing setup. No Android Studio is required for EAS cloud build. See `BUILD_INSTRUCTIONS.md` and `TESTING_DOCUMENTATION.md` for actual verification status.
